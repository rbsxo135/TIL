# Terraform Basic Concept

## Concept
- Infrastructure as Code (IaC) tool
- **Declarative API**
    - Declare a target state of the infrastructure in code
    - The platform tracks the current state and reconciles it by applying only changes if needed
- Automation & Collaboration-oriented
    - Prevents human errors caused by manual GUI infrastructure provisioning
    - Enables infrastructure version control and team collaboration via code repositories
- **State Management**
    - Tracks and stores the actual state of the infrastructure in a terraform.tfstate file
    - Guarantees idempotency &rightarrow; ensures the same result even when executed multiple times
- Multi-Cloud/Service Support
    - Controls various cloud vendors (AWS, GCP, Azure, etc.) and SaaS tools via a unified workflow

## Configure
- terraform init  
    - Initializing step &rightarrow; Create .terraform directory and default config files
    - We can give -backend-config augment to configure a terraform backend
- The state of the infra is recorded in a terraform.state file
- We need to declare **provider**  
    &rightarrow; Declare which cloud service we will use, defaults tags, ...
- We can declare resources in .tf type file  
- terraform plan
    - terraform plans how it will modify the infra
    - plan command doesn't modify infra right away
- terraform apply
    - apply command modifies the infra upon terraform plan
    - It changes a terraform.state file
- If there is a change with AWS consle(not terraform), that change will not be recorded in the terraform.state file  
    &rightarrow; **SYNC BROKEN!** Terraform will plan and apply in way that disable that modification

## Thought
- Terraform has two main pillars: State file management and Dependency tracking
    - &rightarrow; Which means if the State file is lost or code-to-infrastructure synchronization breaks (Drift occurs), troubleshooting becomes extremely complex
- I need to focus on the strictly code-driven nature of this architecture
    - &rightarrow; It is completely improper to directly access the cloud console and manually fix infrastructure when doing operations; every single change must go through modifying the code and running apply
- Since Terraform code can be generated by LLM, we can make AI to build cloud architecture
- It is really important to keep sync intact  
    &rightarrow; If we configure the infra with terrafrom, it is not recommanded to change the infra with console
